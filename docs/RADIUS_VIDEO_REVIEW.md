# 同步显示转速、方向与多半径对照

入口：`output/latest_radius/review.html`。四格视频在 `output/latest_radius/videos/serveXX_radius_compare.mp4`，审核包为 `radius_review_bundle.zip`。

本轮使用 256×256 裁剪图中的四种假设球半径：106.7、117.3、128、160 px，对应基准的 1、1.1、1.2、1.5 倍。同时调整两个相机的球面归一化尺度，重新拟合球面旋转；图像、像素轨迹和源时间都保持相同。它不改变球的物理尺寸，也不是给原转速乘一个修正系数。

## 视频中的数值

每一格按当前源时间显示：

- 当前拟合的转/秒（RPS）与转/分（RPM）。
- 有向单位旋转轴、轴所在的参考相机。
- 两个相机的可见前表面运动箭头、绕视轴的顺/逆时针分量。
- 两侧在相同窗口中的独立转速候选、源帧号、源微秒时间、拟合窗口范围。
- 黄色假设球轮廓、连续至少三帧的真实观测轨迹。

这里“随播放实时显示”指离线拟合值随视频时间更新。20 ms 拟合窗可能包含当前画面之后的观测，不能当成因果在线相机输出。25 FPS 播放按当前 500 μs 源采样约慢放 80 倍，转速仍使用源时间计算。

方向属于相机局部右手系（x 右、y 下、z 远离相机）；前表面中心运动由 `(-ωy, ωx)` 表示。主值为单侧候选时，另一相机的箭头是该模型经相对姿态映射的方向投影，不代表另一次独立方向测量。世界上旋/下旋/侧旋仍需世界方向标定。

## 如何保证四格可比

1. 每次发球的 F59→F3E 相对方向固定为基准结果，其他半径不重新估计相机姿态。
2. 每一帧先从基准组选择联合或单侧候选，其他三组采用同一种来源。
3. 拟合窗口 ID 也固定为基准组；某组该窗口失败就显示 N/A，不换成另一个恰好通过的窗口。
4. 显示值必须在当前源时刻有真实轨迹观测；联合值要求此时刻两侧都有用于模型的观测。不保持旧值，也不把未知填成 0。
5. 独立相机数值也使用主值所固定的同一窗口。缺少整组稳定性的单窗结果明确标为“单窗候选，整组尚未稳定”。

`frame_values.csv` 的 `comparison_window_id` 和 `source_locked_to_baseline` 可以核查这些约束。`window_id` 为空表示该半径的指定窗口不可用。

## 人工审核

网页可选择发球、切换四格或单格放大、暂停、拖动进度及上一帧/下一帧。当前四组数值表与解码到的视频帧同步。也可直接打开 MP4，全屏查看。

先检查黄色球轮廓与真实球边缘是否贴合、轨迹是否仍属于同一物理标记，再比较对应转速。128 px 等于裁剪半宽，160 px 超出裁剪范围，后者是明显的尺度敏感性试验；不能仅因转速更符合预期就当成真实半径。正确球心、半径和标记身份仍需几何证据验证，实际发球 RAW 的时间完整性也尚未核验。

汇总 CSV 只对所有半径均数值可用的相同窗口计算中位数，以避免不同窗口集合改变比较结果。第 05 次缺乏整组稳定结果，汇总保持空值；视频仍能查看个别通过数值门槛的单窗候选及不稳定提示。

## 复现

```bash
bash scripts/pingpong.sh run radius-spin \
  --radius-factors 1 1.1 1.2 1.5 --output output/radius_review_new
```

输出包含四份完整模型 JSON、7 段 1920×1280 四格 MP4、逐帧 CSV/JSON、同窗半径对照 CSV、转速曲线、首帧图、代表帧图和可离线打开的审核页。此前 `output/latest_serve` 的视频和数值保留，新的半径审核使用独立的 `output/latest_radius` 入口。
