# 双视角 clip 的时间与导出范围

审核入口：`output/latest_sync/review.html`。

2026-10-31 已收到并核验实际发球 RAW，最新入口改为 `output/raw_sync_v9/review.html`。两路共 547,522,433 个 CD 事件，完整 SDK 与独立 EVT3 顺序解码一致，无负间隔；7 次发球的 RAW 窗口均与 SDK 顺序读取、带提前量的 seek 一致。890 个旧双路参考帧的事件前景像素与同标签 RAW 重建一致；164 个抽样在 ±10 ms 搜索中最佳偏移均为 0。新版视频始终显示双路 RAW 全视野，再叠加已有裁剪与轨迹，不把缺裁剪显示为缺 RAW。

两台相机的物理时钟同步精度仍未独立确认：RAW 无外部触发记录，全局活动相关峰弱且随时段/极性变化，因此不施加人为时间修正。实际文件证据、全量事件时间编码和复现方法见 [发球 RAW 核验](BALL_RAW_VALIDATION.md)。下面保留 v8 的导出范围分析；v8 是上传 RAW 前的历史报告。

此前双侧裁剪视频使用两台相机导出时间的并集。7 次发球共有 1343 个显示时刻，其中只有 603 个时刻两侧都导出了球裁剪，另外 740 个时刻缺少一侧裁剪。黑面板表示“未导出此时刻的球裁剪”，不能推断原相机未拍到球。此前“没有原始图像”的措辞不准确，生成器已更正。

新审核生成两类视频：

- 原全视野上下文：保留原参考文件同一帧中的左右两个面板，不单独平移某一侧。按原 metadata 的 5000 μs 间隔标出源时间，用于观察球在完整视场中的出现和离开，以及是否有对应导出 ROI。
- 共同时间裁剪：只使用两侧 manifest 的绝对时间戳交集。每帧同时显示各侧原帧号和时间戳，标签时间差为 0。并非把两侧各自第 0 帧拼在一起。例如第 02 次第一对是 F3E 第 80 帧和 F59 第 0 帧。

两类视频的采样率、起点与播放速度不同，不能拿播放进度直接配对。500 μs 的裁剪与 5000 μs 的参考帧也不能逐帧一一对应。当前数据的共同裁剪时刻连续，生成的视频没有压缩掉中间的时间缺口。

本轮确认的是导出层的时间标签和配对方式。原全视野参考自身也有一些时刻只在一侧可见球：这可能涉及视场、遮挡、有效事件活动或实际时钟偏差，当前不能由视频单独区分。原参考视频只有合成帧级的单一时间标注，不是两台相机各自的硬件时间证明。

v8 生成时对应发球 RAW 尚未上传，因此仅能检查导出层。现在已从实际 RAW 按同一 `[t−window,t)` 重建两侧，确认旧参考画面的时间映射。不得通过让球在两侧“看起来同时出现”来选择时间偏移；视野内不同位置本身不能当作同步标志。之后的同步测试 RAW 和当前主从配置不能回填为本批历史发球的同步证明。

现有参考时间字样的自动 OCR 未通过可靠性检查，未作为时间同步证据；本轮重建全视野审核仍明确使用原 metadata 的标注时间。所有转速保持原候选，不因这轮对齐审核被重新标成已验证结果。

复现：

```bash
bash scripts/pingpong.sh run clip-sync --output output/clip_sync_review_new
```

v8 关键输出：`exact_frame_pairs.csv`、`crop_availability.csv`、`clip_summary.csv`、`sync_report.json`。v9 的导出映射字段为真；硬件同步字段仍为 `physical_camera_synchronization_verified=false`，尚无独立物理同步锚点。
