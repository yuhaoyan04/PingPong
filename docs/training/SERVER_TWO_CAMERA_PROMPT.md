# 交给服务器 Codex 的训练与检查任务

请先检查当前解压的数据包、服务器环境，再分别训练 F3E、F59 的单类别标记点检测模型，并在其他发球上做无标签推理和可视化；不要更改原始数据、不要联网传输数据，也不要把未标注图片自动当成负样本。可以联网安装依赖和下载官方模型权重，先检测 CUDA/显存及现有 PyTorch，避免盲目替换已有 CUDA 环境。请记录软件、CUDA、GPU、随机种子和完整配置。

数据结构与约束：

- `datasets/F3E` 与 `datasets/F59` 分别对应两台相机，图片是 256×256、单通道黑白事件占据图，类别只有 `marker`。黑白二值图不等同于二值权重神经网络。
- 根据用户明确要求，每台相机的第 1、6 球已确认标注全部用于训练，不留有标注验证集。`dataset.yaml` 的 `val` 指向训练图片仅为兼容框架必需字段，不是验证集，也绝不能将其结果当成泛化或独立测试指标。不要随机拆帧；相邻图片高度相似。
- 本次没有独立标注验证集或定量测试集，训练结果只能在其他未标注发球做定性推理，须人工审查。
- `unlabeled_inference/<相机>/<发球>/binary/` 是其他发球的未标注图片，只能做定性推理，不带标签、不能计算 mAP 或当负样本。每组保留 `manifest.csv`、相同坐标的 `binary_unfiltered/` 和 `polarity_reference/`。`metadata.json` 中视频路径相对数据包根目录，`reference_videos` 是原双路复核视频。相机与时间戳要匹配；原视频 5 ms 取样，图片每 0.5 ms 导出、1 ms 窗口，两者不是逐帧同步。
- 轨迹是未核验的候选；个别样本 `track_support` 为 `fallback_unverified`，先列出训练/验证中这些样本的数量，评估时单独标明。事件回放曾出现时间戳异常。不要把网络检测结果解释为球速或转速。

具体工作：

1. 使用数据包中的 `python verify_package.py` 检查每张图片、标签、坐标和按发球划分情况；报告标注帧、框、显式负样本、未标注数及 fallback 数量，随机抽图画出两台相机训练图片的 GT 框。检查三目录图像坐标系一致，不能改变图像尺寸而未同步改变框。
2. 采用官方 Ultralytics YOLO11n 检测模型作为起点。检查服务器当前版本是否支持 `channels: 1` 的训练与单通道推理：从首层输入通道、加载 batch 实际 tensor 的形状、1 批 train/predict 冒烟测试确认，而不是仅看 YAML。官方版本若不能稳定支持，记录故障；可对同一单通道黑白数据使用复制到 3 个通道的预训练模型作为明确标注的兼容基线，不要声称它是单通道网络。记录预训练首层权重是否被加载/适配，不要自行假设。
3. 每台相机分别训练，使用 `dataset.yaml`，保证小样本先做短冒烟，然后按显存选择合理 batch 和实际可用 epoch；固定随机种子、`imgsz=256`，谨慎使用可能改变小事件簇语义的增强（初始禁用 mosaic/mixup、颜色抖动和不合理几何变换）；记录配置、训练曲线和 checkpoint。关闭常规验证和验证驱动的早停，若框架最终仍对 `val` 评估，明确那是训练数据，不能当成验证结果；优先保存和报告最终 `last.pt`，不要声称 `best.pt` 经独立验证选出。
4. 仅可输出训练损失和训练集可视化作为拟合自检，不要报告所谓独立验证集 precision、recall、mAP 或混淆矩阵；不要把未标注或未确认的图片作为负样本。
5. 按相机分别对 `unlabeled_inference` 中其他发球的增强图进行推理，输出带框图像和按时间顺序的视频；同时提供相同帧的未滤波图、极性图和原始视频时间定位，供人工区分误检与漏检。没有人工 GT 的组不能计算准确率；确认推理输入预处理与训练一致，记录置信度/NMS 阈值，保存可复现命令与运行环境。
6. 输出简洁报告，列数据数量、环境、训练配置、模型文件、每组样例、疑似失败原因与下一步最需要标注的发球；明确没有独立定量指标，说明标签覆盖有限和样本相关性，避免承诺真实转速/球速精度。

所有模型、日志与可视化放在包外新建的实验输出目录。训练开始前先给出数据审计结果，检查是否需要用户选择会改变实验的事项；不必询问普通执行细节。
